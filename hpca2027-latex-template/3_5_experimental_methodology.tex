\section{Methodology}
\label{sec:methodology}

FourShadow is implemented in Vortex~\cite{vortex}, the open-source RISC-V GPU, and its performance is measured there: in processor cycles on SimX, the Vortex cycle-level simulator, and end to end on an FPGA. It is compared with two NVIDIA GPUs, an RTX 5080 and an H100, for the reasons given in Section~\ref{sec:motivation}. Because the NVIDIA GPUs run different toolkits and FourShadow counts simulated cycles, the platforms are compared only by ratios and trends, never by absolute cycles.

Table~\ref{tab:config} lists the configuration of each platform. FourShadow's entries are Vortex build options, with the tensor core, warp-group MMA and DXA enabled; only the accumulator count $\mathit{NRC}$ is a kernel parameter; parentheses name the part of Section~\ref{sec:eval} that sweeps a value, and bold marks the default (an issue width cannot exceed NW). We name a FourShadow configuration by its issue width (IW, the warps issued per cycle) and its number of warps per core (NW): (IW-1, NW-4) issues from one warp per cycle on a core of four warps; every part that runs four warps per core states it. The configuration matched to the H100 is (IW-4, NW-4) at 32 threads per warp, whose warp-group tile, $64{\times}(2\,\mathit{NRC}){\times}16$, equals that of the H100 instruction \texttt{wgmma.m64nNk16}.

\subsection{Software Configuration}\label{sec:method_sw}

The design-space sweeps run $128\times128\times K$ SGEMM kernels, where $K\in\{128,256,512,1024\}$, change one architectural parameter while holding the rest of the configuration fixed, and compute speedups from total kernel cycles against the baseline configuration each part names in the (IW-N, NW-M) form. The comparisons with the NVIDIA GPUs run instruction-level kernels and count cycles over an in-kernel region. Warp-level MMA is compared at (IW-1, NW-4) with 8 or 32 threads per warp, because there the FP16 sparse speedups of FourShadow and the RTX 5080, over the 17 shapes measured on both, differ by a median of 9.0\% at 8 threads and 6.2\% at 32 threads, less than at issue widths of 2 and 4.
